# Windows 原生 Chrome 采集

Windows 版由 Python 后端、蓝色 Web 界面和 Chrome 扩展组成。扩展使用当前 Chrome profile 的真实登录状态，在最小化的普通浏览器窗口采集搜索、商品详情和卖家页面。商品和卖家页面优先使用搜索窗口中的后台标签页，避免随机等待期间反复创建、关闭 Windows 窗口。后端继续执行筛选、去重、价格历史、AI 分析、通知和定时任务。

## 首次启动

需要安装 Python 3.11+、Chrome，以及构建前端时使用的 Node.js。运行：

```powershell
.\start-windows.ps1 -Setup
```

若 PowerShell 阻止执行，可仅为当前进程放开脚本执行策略：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-windows.ps1 -Setup
```

脚本在 `.venv` 安装 `requirements-native.txt`，Python 依赖使用 TUNA。首次构建前端时会先测试 npm 国内镜像连通性和延迟；路由不符合项目规则时停止安装并提示检查。Windows 运行依赖不包含 Playwright，也不下载 Chromium。

已有环境时运行 `.\start-windows.ps1`，默认启动后端和托盘，保持在后台，不自动打开 Chrome 管理界面。需要启动时显示管理界面，可加 `-OpenBrowser`；`-NoBrowser` 保留为兼容参数。更新到包含托盘的新版本后，先运行一次 `.\start-windows.ps1 -Setup` 安装新增依赖。前端代码更新后运行 `.\start-windows.ps1 -Build`。可用 `-Port 8001` 更换端口。服务监听 `127.0.0.1`；保持终端运行，Ctrl+C 停止服务。

## Windows 托盘与通知

启动时注册蓝色闪电托盘图标，以及名为“闲鱼 AutoAgent”的 Windows 通知应用。图标可能位于任务栏的隐藏图标区域。双击图标打开 Chrome 管理界面；右键菜单提供“打开管理界面”“测试 Windows 通知”和“退出”。选择“退出”会关闭后端、停止运行任务并移除图标。

Windows 通知默认开启，用于启动提示、推荐商品以及需要人工处理的登录、验证码和采集异常。点击通知打开相应网页。可在蓝色界面的“系统设置 → 通知设置 → Windows 通知”中关闭、保存或测试；关闭后托盘继续运行。显示横幅和通知中心记录由“Windows 设置 → 系统 → 通知 → 闲鱼 AutoAgent”控制，勿扰模式可能隐藏横幅。

启动注册同时写入当前用户的应用标识和开始菜单快捷方式，使 Windows 能识别通知来源。`.env` 中的 `WINDOWS_TOAST_ENABLED=false` 可关闭通知，`WINDOWS_TRAY_ENABLED=false` 可在无桌面测试环境中禁用托盘。

## 数据持久化

任务、采集结果和价格历史保存在 `data/app.sqlite3`。Windows 启动入口读取 `.env` 中的 `APP_DATABASE_FILE`，将路径固定为绝对路径并传给后端；默认使用项目根目录下的 `data/app.sqlite3`，重启或更新源码继续使用该数据库。

从 DSM 迁移时，先通过 SQLite online backup 生成包含已提交 WAL 数据的一致快照，验证完整性后替换本机数据库，并复制任务引用的 `prompts` 文件。替换前保留本机旧库，迁移快照及清单保存在 `data/backups`。迁移后的运行状态重置为停止；Cron、账号绑定和筛选条件保持原值。

## 安装并配对扩展

1. Chrome 打开 `chrome://extensions`，开启开发者模式，点击“加载已解压的扩展程序”，选择项目的 `chrome-extension` 文件夹。已有旧扩展时点击重新加载。
2. 登录本机蓝色界面，打开“系统设置 → Chrome 采集”。扩展未连接时直接显示配对令牌，也可点击“获取配对令牌”。
3. 打开扩展的“采集连接设置”，填写 `http://127.0.0.1:8000`（或实际端口）及令牌。点击“读取 Chrome 账户”，选择当前 Chrome 窗口的账户，启用后台采集连接。
4. 在同一个 Chrome profile 中打开闲鱼并登录。管理界面显示扩展在线后，可以使用原来的启动、停止和 Cron 定时任务。

扩展后台通过 Chrome alarms 定期唤醒。命令、标签页和待上报结果保存在扩展本地存储中；网络恢复后重传，上报按 command ID 去重。后端重启会将任务重置为停止，需要重新启动任务。

侧栏显示后端与 Chrome 扩展的连接状态。正常扫描使用后台最小化的普通 Chrome 窗口。登录或验证码出现时，自动显示对应采集窗口；验证完成且页面数据恢复后，窗口回到最小化状态并继续采集。普通页面异常、超时或断线会显示任务状态并推送通知，保持浏览器在后台。无法恢复的页面、已关闭的标签页或不存在的商品，可在管理界面停止任务后重新启动。停止任务只关闭扩展为任务创建的闲鱼标签页，不关闭其他标签页。管理界面、托盘或扩展设置中的“打开账户”仍由用户主动操作并显示在前台。

## 账号与网络

- 账户列表从本机 Chrome 的 Local State 自动读取，显示现有 profiles 的名称。在账号管理中可打开所选账户或为其创建任务；需要切换时，在新账户窗口中安装并配对扩展。
- 自动账号模式使用在线 Chrome profile；固定账号模式要求扩展设置中的“选择 Chrome 账户”与任务所选账户一致。旧版以账号文件绑定的固定任务，需重新选择本机 Chrome 账户。
- 固定账号的扩展离线时，任务显示对应 Chrome 账户的断线提示，包括排队或随机等待期间；其他账户在线也不能代替该账户。重新打开对应账户的 Chrome，扩展恢复连接后继续采集。断线检查不依赖页面命令是否已下发，Windows 通知失败也不会停止监测。
- 轮换模式在已连接的 Chrome profiles 之间选择账号。需要分别打开不同的 Chrome profile、登录对应账号并配置扩展。同一个 profile 的采集任务按顺序执行，AI 分析仍可并发。
- 浏览器网络使用 Chrome 自身的系统代理或 profile 配置；原爬虫的代理池不会替扩展切换 Chrome 代理。AI 请求继续使用后端配置。

## 采集范围与验证

扩展观察页面正常发出的 fetch、XHR 和 JSONP 请求，读取搜索、详情、用户资料、商品和评价数据；DOM 作为搜索和详情的补充。筛选和分页通过页面控件操作；后端再次执行价格、区域、包邮、关键词及个人卖家条件检查。无法确认个人卖家身份时不会放行。页面变化时可能需要调整扩展中的解析器和选择器。

发布时间筛选（最新、1 天内、3 天内、7 天内、14 天内）由扩展自动选择页面已有的菜单项，检查当前筛选标题，避免重复点击取消条件。菜单由 CSS 悬停控制时也可在最小化窗口中执行；等待结果时扩展继续轮询，采集等待筛选后的搜索响应。无法生效的筛选会有限重试并报告任务失败。更新到扩展 2.0.3 时，在 `chrome://extensions` 点击本扩展的重新加载；旧版本停在发布时间筛选的任务会在扩展更新且页面数据正常后自动继续。

扩展 2.0.4 会将任务最低价、最高价自动填入闲鱼页面的价格区间，点击“确定”后等待对应区间的搜索结果，再开始采集。支持只填写一端，并清空另一端的旧值；页面价格输入遵循闲鱼的非负整数金额限制。后端继续按原版逻辑核对商品价格。更新后在 `chrome://extensions` 重新加载本扩展。

任务内的浏览器采集按线性阻塞顺序执行：随机等待 20–40 秒，打开商品并采集详情；随机等待 5–15 秒，打开卖家个人主页并采集；当前商品完成后，再开始下一个商品的等待。当前页商品全部处理后再翻页。登录或验证会阻塞当前采集链，恢复后继续原页面。AI 分析独立按 AI 设置的并发数执行。

在“系统设置 → Chrome 采集”设置每个任务的采集内存预算，默认 2 GB，支持 0.5–1024 GB。详情、卖家资料和翻页共享预算。日志显示每页待采集和已处理/重复商品数量、随机等待时长及实际打开页面的时间；界面显示等待倒计时。等待由后端调度，扩展 2.1.1 无需重新加载即可使用此节奏。

普通版 Chrome 扩展只能读取 JS heap，无法取得完整的任务进程内存。预算按每个采集窗口 `max(256 MB, 2 × JS heap + 128 MB)` 的峰值估算，预留 DOM、图片与原生开销；这是采集窗口的准入预算，不能保证 Chrome 的实际进程内存不超过设定值。设置界面显示窗口数与估算用量。保存后立即参与调度，降低预算或页面内存增长时暂停新增窗口，已经开始的采集继续完成，关闭窗口后释放预算。搜索窗口保留到整轮浏览器采集结束，避免最后一页的随机等待期间关闭该账户的最后一个窗口，导致 Chrome 卸载账户并中断扩展；分析队列满时采集会等待。

各窗口的命令、翻页检查点和待上报结果独立保存，扩展后台重启后继续推进，网络恢复后按 command ID 重传去重。完成验证且该页面数据恢复后自动继续。

扩展 2.1.1 区分“下一页控件尚未渲染”和“最后一页”：读取搜索响应中的 `numFound` 核对总页数，等待分页控件就绪，临时点击失败时继续重试。后续页也会检查响应的请求页号，避免把上一页数据标成下一页。日志记录任务页数上限、每页分页状态，以及达到上限或页面确认最后一页的结束原因。更新后在 `chrome://extensions` 重新加载扩展。

扩展 2.1.3 让商品和卖家页面优先复用后台搜索窗口，使用 `active: false` 的标签页；完成后只关闭对应标签页，随机等待期间保留搜索窗口。内存预算仍逐个采集页面预留，多个标签页共用窗口不会减少预算。只有登录验证会恢复并聚焦采集窗口，同一次暂停不会因提示文字变化而重复抢焦点；同一窗口的验证全部完成后自动最小化。用户已导航到其他页面的搜索窗口不会被复用。更新时需在采集账户的 `chrome://extensions` 重新加载扩展。当前模式保留普通 Chrome 的 profile 和扩展能力，使用后台最小化窗口。

卖家商品和评价随页面滚动加载，单个列表最多收集 500 条；保存的数据注明采集范围。普通 Chrome 在最小化或系统休眠时仍可能被节流；长时间无响应的任务会等待你检查并继续。

测试命令（现有 conda 风格环境也可使用 `.venv\python.exe`）：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/unit/test_native_browser_service.py tests/integration/test_api_browser.py
.\.venv\Scripts\python.exe -m pytest tests/unit/test_windows_desktop.py tests/integration/test_api_settings.py
cd chrome-extension
npm test
```

Linux / DSM 的默认运行方式保持为原有采集器；可通过 `SCRAPER_BACKEND=playwright` 显式选择。Windows 启动脚本固定使用 `native_chrome`。
